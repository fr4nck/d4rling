## Target-inventory result and source-level identification

On the 10400, both the `cmake --build "$BUILD" --target help` and
`ninja -C "$BUILD" -t targets all` inventories completed. The filtered
terminal excerpts matched mainly **paths** under
`src/external/xnu/darling/src/libsystem_kernel`, and therefore did not
identify the top-level target names. **The failure remains a name/target
selection problem, not evidence of a failed CoreFoundation compiler.**

Further GitHub source inspection of the **pinned** submodules identified:
`darling-corefoundation` at
`a3640a77410cf1825f7855172b1551ae7917c461` invokes
`add_separated_framework(CoreFoundation ...)`. The historical CMake macro
creates `CoreFoundation_i386` and `CoreFoundation_x86_64` as build
targets, while `CoreFoundation` itself is an **IMPORTED** library target.
Similarly, the pinned libc and libsystem CMake files define `system_c`
and `system`. These identities are **source-derived only** until their
presence is queried in the generated 10400 Ninja tree.

**This qualifies build/link completion only.** It does not independently
verify the resulting Mach-O file format/slice, loaded dependencies, the

execution. `system_c` and `system` target presence was verified;
their final binaries were not independently inspected.

## Follow-up result: universal CoreFoundation Mach-O PASS

The 10400 operator confirmed that
`src/external/corefoundation/CoreFoundation_i386` is a
**Mach-O i386 dynamically linked shared library**, not an ELF host binary.
The bundled cctools `lipo -info` reported a non-fat i386 file.

The `CoreFoundation_x86_64` target was then built **PASS** with two
parallel jobs. The actual outputs were inspected:

| File | Architecture verified |
| --- | --- |
| `src/external/corefoundation/CoreFoundation_i386` | Mach-O i386 |
| `src/external/corefoundation/CoreFoundation_x86_64` | Mach-O 64-bit x86_64 |
| `src/external/corefoundation/CoreFoundation` | Universal/fat Mach-O with **i386 and x86_64** |

The bundled `lipo` independently confirmed:
`Architectures in the fat file: ... are: i386 x86_64`.
Linker warnings involving duplicate Objective-C `NSObject` symbols remained
nonfatal and are not claimed fixed. C: free was approximately **133 GB**.

**Qualification boundary:** the build and both Mach-O slices are now
confirmed, but no full private installation, dynamic library resolution,
`dyld` guest execution, Carbon guest probe, Logic 8, QuickTime, JACK or MIDI
has been demonstrated on the 10400.
