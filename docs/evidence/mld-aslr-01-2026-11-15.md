## Contrat documenté et chemin exécuté

Le [manuel Linux personality(2)](https://man7.org/linux/man-pages/man2/personality.2.html) documente la lecture avec `0xffffffff`, le bit `ADDR_NO_RANDOMIZE` et le retour d'erreur -1. Le correctif lit la personnalité, puis enlève **ce seul bit** avant l'exec de réessai lorsque le placement haut i386 est occupé et qu'un budget reste disponible. Les placements Darwin restent explicites. Les autres bits sont conservés ; une impossibilité de lire/modifier la personnalité ne supprime jamais la borne des relances.

Dans le code réellement employé, `libsystem_kernel` traite le flag spawn `0x0100` en positionnant `LINUX_ADDR_NO_RANDOMIZE` avant exec. Un parent **Mach-O x86_64** démarre l'enfant **Mach-O i386**, le chargeur ELF64 passe au chargeur ELF32 ; celui-ci vérifie la plage pile/commpage. Avec le bit actif, la référence garde un placement Linux défavorable ; le candidat peut obtenir un nouveau placement à la relance. Cette chaîne utilise les vrais frameworks/libSystem Darling, sans adaptateur hôte.

## Intégrité, tentatives et limites

Les sept essais finaux retrouvent **41 → 41 montages hôte** et aucun PID dans leur namespace possédé. Le runtime S4 d'origine est revérifié sur **6 013 fichiers**, inchangé. Canon toujours propre à `747670a53d5a73af64470e5f60f8f3611a09a245`, source du banc core propre à `4be2603c…` ; le checkout Claude a avancé de `8ec5c629…` à `e61f9088…` par son chantier, sans écriture du lot. Aucun préfixe historique, QuickTime, CoreAudio, libdyld, sous-module ou autre branche modifié.

Tentatives conservées privées et exclues du verdict : transfert Git amont en thin-pack rejeté avec `6 unresolved deltas` (fichiers exacts ensuite récupérés via API GitHub, blobs vérifiés) ; premier candidat rejeté à la revue pour placement du bloc dans `reexec32` ; premier build du test hôte refusé par `-Werror=misleading-indentation`, corrigé dans la fixture. La qualification repose seulement sur la recette finale et le candidat placé dans `ensure_top_range_free`.

Limites : aucune qualification lldb/debugserver (l'hôte conserve `vm.mmap_min_addr=65536`, alors que l'amont rapporte ses essais avec une valeur ≤4096) ; aucun changement global pour lever cette précondition. Pas de campagne dédiée sur un invité x86_64 démarré avec disable-ASLR, pas d'estimation statistique du taux de collision ni de preuve exhaustive pour tous les noyaux. Les témoins Carbon réutilisés gardent leur portée S4 : aucune qualification GUI ou application entière n'en découle.

**Verdict : MLD_ASLR_01_PASS**, correction source ciblée publiable sur D4rling master, garde `559f9911` conservé et qualifié.
